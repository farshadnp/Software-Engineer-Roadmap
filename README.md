# مسیر آمادگی Software Engineer با تمرکز بک‌اند .NET

نسخه ۲ — ۲۰۲۶-۰۹-۰۶. هدف اعلام‌شده: حداقل Mid-level. زمان اعلام‌شده: روزانه حداقل ۳ ساعت. نقطه شروع: C# پایه، آشنایی با ASP.NET Core و Git روتین؛ عمق مهارت و SQL هنوز ارزیابی نشده‌اند. بازار هدف هنوز مشخص نیست. روش ترجیحی: یادگیری مفاهیم کتاب، کدریویو تعاملی، سؤال‌وجواب و چرایی پیاده‌سازی؛ گاهی کدنویسی کوچک توسط یادگیرنده.

از [ROADMAP.md](ROADMAP.md) شروع کن. برنامه ۸ هفته و ۱۶۸ ساعت است؛ موعد شروع با اولین جلسه ثبت می‌شود. این زمان یک برآورد آموزشی است، نه تضمین استخدام یا احراز سطح Mid.

## شروع و ادامه

برای شروع بنویس: «طبق MENTOR-PROTOCOL.md جلسه W1D1 را شروع کنیم.»

برای ادامه در گفتگوی تازه همین پروژه بنویس: «README.md، MENTOR-PROTOCOL.md، progress.json و آخرین SESSION-LOG.md را بخوان و از next_session_id ادامه بده.»

به حافظه چت اتکا نمی‌کنیم. پایان هر جلسه شواهد، امتیاز و قدم بعد در فایل‌ها ثبت می‌شود. مطالعه بیرون از گفتگو تا زمان گزارش تو قابل مشاهده نیست. فایل‌ها باید در همین پروژه در دسترس بمانند؛ ثبت تغییرات در Git و پشتیبان‌گیری کمک می‌کند سابقه از بین نرود.

## ابزار پیشنهادی

همین پروژه و فایل‌های نسخه‌پذیر برای شروع کافی‌اند. برای برد بیرونی، GitHub Issues + Projects بهترین انطباق را با این برنامه دارد: هر جلسه یک issue با شناسه ثابت، هر هفته یک milestone و هر تمرین کدنویسی متصل به PR/commit. GitHub در فهرست پلاگین‌های قابل نصب است، اما اکنون نصب یا اتصال آن تأیید نشده و برد بیرونی ساخته نشده است. قابلیت برد و جدول و اتصال به issue/PR در [مستندات GitHub](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects) توضیح داده شده است.

Automation با شناسه automation فعال شده: روزانه ساعت ۱۹:۰۰ (زمان پیش‌فرض انتخاب‌شده با قصد Asia/Tehran)، جمعه‌ها مرور هفتگی در همان نوبت. پایان دوره پیگیری ۲۰۲۶-۱۱-۰۱ است؛ این تاریخ موعد بازبینی برنامه است و به معنای اتمام خودکار یادگیری نیست. هر اجرا باید از فایل وضعیت بخواند و بدون مشارکت کاربر پیشرفت نسازد. برای کار با فایل محلی، کامپیوتر و برنامه باید روشن و پروژه در دسترس باشد؛ [راهنمای رسمی زمان‌بندی](https://learn.chatgpt.com/docs/automations?surface=app).

اگر بعداً GitHub را وصل کنیم، progress.json مرجع اصلی می‌ماند و شناسه issue/PR به شواهد اضافه می‌شود؛ از دو فهرست مستقل و ناسازگار پیشرفت جلوگیری می‌کنیم. نصب افزونه یا وجود برد به‌تنهایی مدرک یادگیری نیست.
